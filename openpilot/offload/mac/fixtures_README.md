## Record byte layout

Each `.enc` file is a **concatenation of records with no file header or
trailer**. Every record is little-endian, **32-byte header first, then the AU
payload**:

| offset | size | field | notes |
|---|---|---|---|
| 0 | u32 | `nbytes` | byte length of the AU's Annex-B bytes **including** start code(s) |
| 4 | u32 | `frameId` | device frame id |
| 8 | u32 | `encodeId` | device encoder id (1:1 monotone with frameId) |
| 12 | u64 | `timestampSof` | device ns, start of frame |
| 20 | u64 | `timestampEof` | device ns, end of frame |
| 28 | u32 | `flags` | device encoder flags |
| 32 | *nbytes* | AU bytes | Annex-B HEVC access unit, copied verbatim |

Fixed 32-byte header per record; total record size = `32 + nbytes`.
Canonical parser:

```python
import struct
HDR = struct.Struct("<IIIQQI")          # 32 bytes
nbytes, frameId, encodeId, sof, eof, flags = HDR.unpack_from(buf, off)
au = buf[off + 32 : off + 32 + nbytes]  # next record begins at off + 32 + nbytes
```

### What an "access unit" is here

An AU = one coded picture. It starts at the **first VCL NAL** whose
`first_slice_segment_in_pic_flag == 1` (MSB of the byte after the 2-byte NAL
header, `data[nal_start+2] >> 7 & 1`) and runs through the last VCL NAL of that
picture. The AU span therefore **starts at the first VCL start code**, so the
90 bytes (`VPS+SPS+PPS` + their 4-byte start codes) at the head of each `.hevc`
file are **not** part of any record.

This is required for the core invariant below, and it means **a `.enc` file is
not decodable standalone**: the consumer must already own the stream's
parameter sets. If that is not the case, a sidecar carrying the VPS/SPS/PPS NALs
must be added — the record spec is intentionally left unchanged so the invariant
still holds for record 0. (Open item — see "Deviations" below.)

## Core invariant

For every record, the AU byte length equals that frame's qlog `EncodeIndex.len`:

```
sum(AU nbytes) == sum(qlog len)
  narrow: 75,017,454 == 75,017,454   (1200/1200 records, 0 mismatches)
  wide  : 74,967,722 == 74,967,722   (1200/1200 records, 0 mismatches)
```

`make_fixture.py` asserts this per record and exits non-zero on any mismatch;
the full run reported **0 mismatches for both streams**. (This also pins each
`.hevc` file size exactly: `Σ AU bytes + 90 B of parameter sets`.)

## `timestampEof` policy, and deviations from the original brief

Two deliberate deviations; both are auditable in the code and in the run log.

**1. `wide.enc` is built from `ecamera.hevc`, not `fcamera.hevc`.**
The brief assumed the wide stream reuses the front-camera bitstream. Measured on
the on-disk files:

| AU span vs | `narrowRoadEncodeIdx.len` | `wideRoadEncodeIdx.len` |
|---|---|---|
| `fcamera.hevc` AUs | **1200 / 1200 match** | 0 / 1200 |
| `ecamera.hevc` AUs | 0 / 1200 | **1200 / 1200 match** |
| `dcamera.hevc` AUs | 0 / 1200 | 0 / 1200 |

`wideRoadEncodeIdx` is the comma three *encoder / right* camera == `ecamera`
(also implied by `INTERFACES.md`: wide decodes to `wideRoadEncodeIdx` on the same
device). Pairing wide with `fcamera` would fail the brief's own core assertion
for all 1200 records, so the invariant was kept and `narrow ← fcamera`,
`wide ← ecamera`. Camera selection is **not** a heuristic argmin: every on-disk
camera is scored and exactly one must be an all-zero match, else `make_fixture.py`
exits with a fatal error.

**2. `timestampEof` is preserved, not synthesized.**
The brief said qlog has no `timestampEof` (0) and asked to synthesize
`timestampSof + 50 ms`. On this route it is present and nonzero: for every
narrow **and** wide entry, `timestampEof − timestampSof == 14,697,000 ns`
(uniform ≈14.697 ms — a plausible real sensor readout). Real values are written
untouched. The `+50,000,000 ns` synthesis exists **only as a fallback** for any
individual record whose `timestampEof` is genuinely 0; the summary reports the
count of synthesized records (`eof_synth`). On this segment that count is **0**
for both streams. Nothing in the frozen `offload/contract.py` (`FrameEvent.
timestamp_eof` = "device ns") wants a marker value.

## Regenerating

From the repo root:

```bash
PYTHONPATH=$PWD:$PWD/opendbc_repo:$PWD/msgq_repo:$PWD/tinygrad_repo \
  .venv/bin/python openpilot/offload/mac/make_fixture.py \
    --route-dir /Users/adam.durham/comma-routes/00000149--4a4df1cf8a--36 \
    --out-dir   openpilot/offload/replay/fixtures/00000149--4a4df1cf8a--36 \
    --cam both
```

Flags: `--route-dir` (required), `--out-dir` (required),
`--max-frames N` (default: all 1200), `--cam narrow|wide|both` (default `both`).
Exit code is 0 only if every record satisfies AU-length == qlog-len and each
file's framed size matches its on-disk size. Deps: `zstandard` + `capnp` from the
repo venv (no installs).
